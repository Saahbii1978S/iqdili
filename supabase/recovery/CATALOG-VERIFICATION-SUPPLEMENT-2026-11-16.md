## Exact application constraints observed
The catalog query returned the following application constraints (managed Supabase schemas are excluded):

### Private
- `ask_rate_limits`: PK on `fingerprint`; CHECK `request_count >= 0`; CHECK fingerprint matches `^[a-f0-9]{64}$`.
- `pending_image_rate_limits`: PK on `fingerprint`; CHECK fingerprint matches `^[a-f0-9]{64}$`; CHECK `request_count >= 0`.
- `site_visit_config`: PK on `id`; CHECK `id = true`.
- `site_visitor_days`: composite PK `(visitor_id, visit_day)`; CHECK `visit_count > 0`.

### Public
- `admin_notification_events`: composite PK `(user_id, event_type)`.
- `admin_role_events`: PK on `id`; CHECK action is one of `granted` or `revoked`; actor and target user FKs to `auth.users(id)` with ON DELETE SET NULL.
- `admin_status_audit`: PK on `id`; actor FK to `auth.users(id)` with ON DELETE SET NULL.
- `admins`: PK on `user_id`; FK to `auth.users(id)` with ON DELETE CASCADE.
- `job_posts`, `market_posts`, `real_estate_posts`, `service_requests`: each has a PK on `id` and nullable `user_id` FK to `auth.users(id)` with ON DELETE SET NULL.
- `staff_roles`: PK on `user_id`; FK `user_id` to `auth.users(id)` with ON DELETE CASCADE; nullable `granted_by` FK with ON DELETE SET NULL; CHECK role is exactly `moderator`.
- Legacy `services`, `jobs`, `market`, `properties`, and `realty` each have a primary key on `id`.

## Implications for the local test environment
This verification is enough to strengthen the table/constraint/policy/view inventory, but it is **not** enough to call the local database a faithful restore. A faithful local baseline still needs complete, exact DDL and ACL reconstruction, including:
1. All table and column grants, schema grants, and default privileges.
2. Full definitions and execution grants for all application functions, including exact SECURITY DEFINER/search_path properties.
3. Trigger definitions and ordering, plus the application event trigger.
4. Sequence definitions, ownership/dependencies, and grants.
5. Storage bucket metadata and all storage policies (not only public-read policies).
6. Required Auth-local compatibility and the scheduled expiry job definition.
7. An object-by-object comparison after applying the local-only baseline.

The local Supabase config deliberately keeps migrations and seed disabled until that work is complete. Do not enable migrations, generate a guessed baseline, or run any SQL against production as a shortcut.
